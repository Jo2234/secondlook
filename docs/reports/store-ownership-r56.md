## Production repairs

R55-P1-01 is addressed in source, not runtime accepted. Store retains its complete generated lock payload and captured creation identity. Shutdown first fences writes, joins the commit tail and owned operations, then reads the actual lock through a captured handle with a 4096-byte cap, fd-stat, cap+1/actual EOF and pre/fd/post identity checks. The actual read handle must close successfully before the payload is usable. The entire original payload must match; merely finding an equal adopted lockId is insufficient. Missing/unreadable/malformed/mismatched locks reject and latch UNKNOWN. Immediately before unlink the original identity is checked again. Only actual unlink, awaited directory sync (including its actual handle close), the final IO join and owner release can fulfill Store.close. There is no ENOENT success, mismatch log-and-fulfill, retry, or unproved storeClosed assignment. Repeated Store.close returns the same retained task.

R55-P2-05's production portion is addressed in source. A StoreIOOwner exists before Store.acquire in the real factory. Default/standalone Store.acquire constructs the same resident ownership primitive before beginning any asynchronous acquisition. A strong module registry keeps failed owners, acquisition directory/lock metadata, the actual Store when constructed, actual FileHandle objects, actual operation promises, rejected-close tasks and internal faults reachable even if Store never fulfills. Every explicit open at the lock, state/media read, temporary commit, media write and directory sync boundaries captures its returned handle immediately before further fallible work. Successful actual close alone deletes the handle. Rejected close preserves both the object and its original task; repeated requests return that outcome without another actual close. Work and close faults are independently observed. No GC, numeric fd retry, shadow descriptor, process/group probe, disappearance or OS identity helper substitutes for closure.

Commit serialization captures the previous tail before publishing the new operation. Existing temporary_open/write/sync/close/rename/directory_sync stages and not_committed versus unknown classification remain; memory updates only after rename and directory sync. Close faults are no longer suppressed: a cleanup-close rejection is returned while the original commit stage remains retained. Additional IO/admission faults conservatively fence later writes and positive closure. Media writes, reads/removals, startup tmp removal, cleanTmp and directory sync are retained actual operations; final Store.close itself is deliberately outside their join set to avoid self-await. A failed commit retains its original stage object and the raw internal fault without exposing filesystem error messages.
