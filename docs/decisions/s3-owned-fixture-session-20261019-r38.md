That source returns an async request listener, exposes native incoming/outgoing bindings and supports overrideGlobalObjects:false and autoCleanupIncoming:false. Its stream writer calls reader.cancel(error).catch without awaiting the actual cancel result; its returned handler promise and response close are insufficient release proof. It disables detached adapter input draining/global Request/Response replacement, owns unread input draining explicitly, and retains actual IncomingMessage, ServerResponse, Request, Response, original body reader, reader.closed, each read, actual cancel promise, releaseLock outcome, adapter task and socket close observations.

The transport-only wrapper returns actual cancellation rejection while observing it independently even if the adapter drops it. It preserves byte chunks, status, statusText and headers; it does not fabricate API JSON or business state. EOF releases the original reader only after the read is settled. Cancellation joins its actual operation and pending reads before releaseLock. releaseLock is synchronous and any throw is sticky failure, not a fictitious async completion. Native premature response close/error or incoming aborted/incomplete/error remains sticky UNKNOWN even if the app already returned. The wrapper also cancels a body that arrives after native disconnection. Unresolved reads/cancel/adapter tasks retain their records indefinitely until actual settlement; a deadline does not delete them.

The combined HttpListener.close promise independently starts native close, request/body/adapter joins and socket joins, including requests arriving during close. Physical server close is not presented to HttpLifetime as whole-bridge release. Unproved joins or a failure cannot reach Store.close. Store.close is additionally guarded by positive native release and the original HttpLifetime's app/startup/Runner joins and failure latch. Native close is attempted even when another join fails. A failed join keeps observers, ownership and lock. There are no new native grace timers. Expire fails the owner, requests cancellation/destruction on captured objects and retains all joins; it does not force exit or erase UNKNOWN.

These are source design claims, not a native/stream race test result. Required later cases include delayed original read/cancel/release failure, dropped adapter cancellation rejection, native finish-before-handler-settlement, incoming abort, premature close, cap refusal, pending/failed bind, native close error with independent blocked joins, and late request/body creation during stop.
