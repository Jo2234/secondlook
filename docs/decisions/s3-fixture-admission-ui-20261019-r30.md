The accepted implementation plan §§4.5, 5, 6, 9.1 and S3 calls for fixture seller generation with explicit cost confirmation. The current owned fixture route now commits request identity and ordered jobs before returning `{mode,jobs}`. The read-only `GET /api/tryon-requests/:requestId` returns that same envelope in stored request job order; a missing 404 never proves an original POST had no effect. These are existing server seams; this change does not alter them or implement retry/recovery.

`fixture-admission.ts` is the production network-free ownership boundary, used by App and SellerApi. A review freezes listing ID/updatedAt/title, first original photo, ordered model IDs, declaration and one UUIDv4. A synchronous claim precedes asynchronous preconfirmation reads. The page rechecks health, saved listing, synthetic models and ledger, then authorizes one transition to POST with the original zero-cost payload. Changes to saved timestamp, listing/photo, declaration, models, readiness, quality or health refuse before POST. Production shared schemas are reused; the quality gate and thresholds are unchanged. The server remains authoritative for gate evaluation at commit.

The API retains its existing same-origin HTTP loopback check, exact fixture response check, timeout, byte cap, abort disposal and lack of automatic retries. The blanket admission block is narrowed only for reviewed fixture generate. User retry remains blocked, and no buyer/live/recovery UI is enabled. Success and lookup require complete shared job envelopes and exact request/listing/photo/model/category/order correlation, unique 1–2 jobs and fixture mode. Once known, job IDs must remain identical. Only exact known pre-effect refusal status/code/envelopes are definitive; conflict, 5xx, malformed success/error and transport failure retain unknown ownership.

An unknown POST retains its original frozen context in page-module memory across React remounts and blocks further writes/new admission. Explicit GET reconciliation can adopt matching original jobs without POST. Missing/malformed/mismatched/unavailable lookup retains unknown. There is no clear-unknown, retry, automatic lookup or force-unlock action. Known accepted ownership is retained when a later read fails. Cancel acknowledgements remain visible when a following read fails; job refresh and publication retain generation/mounted fencing and polling ownership still depends on job IDs/selection/action epoch, not fetched array identity.

The UUID is visible and selectable for copying. Full navigation/reload loses page memory; the UI describes that limitation. UUID-only lookup then displays inspection results without adoption or admission authority. Ledger entries unknown to this page session conservatively block all new admission, including unrelated listings. Known admitted listings and listings with existing result IDs cannot be regenerated here. These restrictions intentionally avoid presenting a new request as a supported user retry.

Limits of the existing seam: no client can reconstruct a lost declaration/model review from a UUID alone, prove non-admission from 404, coordinate arbitrary independent tabs, or atomically compare listing updatedAt in POST (the server request schema has no expected-version field). The UI performs the existing pre-POST GET check and correlation; it does not claim cross-tab exclusion or server-side compare-and-swap. If those stronger guarantees are required, stop that portion and separately review a server contract for an expected listing revision plus durable admission inspection/context. No such server/schema change or bypass is made here. A reload while a server commit is still pending is likewise not a durable client recovery contract; do not retry the lost request after navigation. Persisted browser context and automatic recovery are deliberately absent.

The original-first gallery, fixture watermark/disclaimer, listing provenance, buyer disabled explainer and existing source/evidence outside the six-path scope are preserved. Existing R17 and R29 JSON receipts were read as named historical evidence only: R17's qualified durable-ID/uncertain/lookup checkpoint and R29's five unique publication cases plus historical zero strict diagnostics are not rerun or extended by this source change.
