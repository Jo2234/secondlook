# S1 source review R1 — changes required before acceptance

Reviewer: GPT-6 Astra HIGH, 19 October 2026, same quota-fallback lead. Reviewed source a327547 and ancestor 323ecd5. This is source reasoning; tests have not run and the stage is not accepted.

1. **Unknown error keys must use own-property lookup.** `mapError` reads `ENGINE_ERRORS[engineError]` on a normal object. Unknown provider codes such as `constructor`, `toString` and `__proto__` select inherited values instead of the required yc_engine fallback, yielding an invalid UserError. Use an own-entry check or a prototype-free map. Add adversarial unknown-code tests verifying complete code/messageKey/retryable/upstream values. This is also necessary for accepted F21 own-entry coverage.
2. **Limiter failure during task GET must consume the retry budget.** `step` handles limiter_failed for task_get by scheduling a fixed one-second wait, without recording get_error or consuming the consecutive retry allowance. §5.8 says a GET limiter failure counts as a GET error. Route it through the same bounded retry/backoff/jitter accounting and terminal disposition as a failed GET, without incrementing actual HTTP getCount for requests never sent. A deterministic sequence of repeated limiter failures must exhaust the allowance; no request is sent and no endless sequence until the wall deadline substitutes for the explicit retry cap.
3. **A result URL refresh is at most one task GET.** After download_failed(expired), the reducer records result_refresh and requests one GET, but poll_running/get_error/limiter_failed can then re-enter ordinary polling and issue more GETs. The §5.8 download phase permits ≤1 refresh GET; F7 requires exactly one refresh. During refresh, a non-success/failed GET ends result_download_failed (ledger possibly_spent, taskId retained), rather than polling again. Preserve the phase/attempt deadline and cancellation. Test expired URL→refresh running and expired URL→refresh transport failure; advancing time or poll_due cannot produce a second refresh GET. A successful refresh permits the second download; another expiry fails without another refresh.

The accepted R2 specification also needs implementation in the same original Sol slot1. Keep these changes separate from installation grants: first lockfile proposal on frozen SHA, then a reviewed source revision/updated SHA. No new dependencies, threshold changes, live calls, buyer enablement or automatic engine POST retry.
